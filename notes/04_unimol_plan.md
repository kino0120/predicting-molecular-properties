## 1. 方針が決まるまで

| 検討したもの | 結論 | 理由 |
|---|---|---|
| 2位方式の Transformer をそのまま再現 | 不採用（予備） | 2位は GPU 十数台で数週間。Pro の予算（A100 で約8〜18時間）では -3.16 の再現も難しい。真似るだけなので、2位を超える見込みも薄い |
| LightGBM | 不採用 | 上限が -2.0〜-2.1（詳細は 03 のメモ） |
| GPT などの文章用 LLM を転移学習 | 不採用 | LLM も中身は Transformer で、事前学習は文章。SMILES（文字表現）では 3D の形（二面角など）が抜け落ちる。2024年の研究では、QM9 の物性で 3D の専用モデルより誤差が5〜17倍大きい。数十億パラメータの fine-tune は予算も超える |
| EPT（Equivariant Pretrained Transformer） | 見送り | タンパク質寄りのモデルで、重みの公開が確認できず、小分子の物性での実績もない |
| **Uni-Mol（2022, ICLR 2023）** | **採用** | 下記 |

## 2. Uni-Mol を選んだ理由
1. **原子ペアごとの表現を最初から持っている**。J は原子ペアの値なので、そのまま J を予測する出力部分を足せる。1位の「ペアもノードにする」考え方を、事前学習付きで使えるイメージ
2. **小分子の 3D 構造 2.09億個で事前学習済み**。予算の少ない今回、「少ない学習で早く精度が上がる」効果が期待できる
3. **2位方式より軽い**。1分子を1回処理すれば全ペアを予測できる（1エポック約8万分子。2位方式は約79〜140万本）
4. **水素込みの重みがある**（`mol_pre_all_h_220816.pt`）。J は必ず H が関わるので必須の条件

**リスク**: CHAMPS で Uni-Mol を使った事例は見つかっていない（実験になる）。事前学習の構造は RDKit の簡易的なもので、今回の DFT 構造とは少し違う。

## 3. 実装のポイント
- 当初は、`unimol_tools` が PyTorch 2.4 以上を要求し Intel Mac に入らなかったので、**本体のコードだけを自前で移植**して公開重みを読み込んでいた（v1〜v3 はこの版で学習）
- 2026-10-26: 学習は Colab だけで行うので、**`unimol_tools==0.1.6` の `UniMolModel` から部品（埋め込み・距離の展開・エンコーダー）を import する形に変更**。同じ重みなら移植版と出力が完全に一致することを確認済み（差 0）
  - `MolTrain` などの公式の学習の仕組みは「1分子に1つの値」しか扱えず、`UniMolModel.forward` はペア表現を捨てるので、エンコーダーを直接呼んで最終のペア表現を受け取る
  - **語彙の番号は自前で振る**: `unimol_tools` 0.1.5 以降の `Dictionary` は特殊トークンを先に `[CLS]=0, [UNK]=1, [PAD]=2, [SEP]=3` で登録し、ファイルの行順（重みの学習時の番号）とずれる。原子（C=4 など）は同じ
  - `--no-deps` で入れる（依存どおりだと numpy が入れ替わり、ランタイムの再起動が必要になる）。dropout は 0.1 固定なので設定値で上書き
- 重み: Hugging Face の dptech/Uni-Mol-Models。本体は約4,730万パラメータ（15層・512次元・64ヘッド）
- 語彙はファイルの行順: `[PAD]=0, [CLS]=1, [SEP]=2, [UNK]=3, C=4, N=5, O=6, H=8, F=10`、最後に `[MASK]=30`（計31語）
- 入力: `[CLS] 原子… [SEP]`。座標は重心を原点にし、[CLS]/[SEP] は原点に置く
- **移植が正しいかの確認**: 事前学習の距離予測部分（dist_head）に**最終のペア表現**を入れ、出力を**平均 6.3126・標準偏差 3.3899 で元の単位に戻す**と、原子間距離の誤差は**平均 0.05Å**（手元で確認済み）
  - 最初は変化分のペア表現（delta）を使って 0.98Å になった。delta は事前学習では座標の更新に使われていた表現で、距離の予測用ではなかった
- J の出力部分: ペア (i, j) について [x_i, x_j, x_i*x_j, 最終のペア表現 ij, ji, type の埋め込み] を MLP に入れ、type ごとに4成分（fc/sd/pso/dso）を出して合計を J とする。(i, j) と (j, i) の平均を取るので、入れ替えに対して対称
- 損失: type 別 log(MAE) の平均（コンペの指標そのもの）。4成分の補助損失は `contrib_w` で切り替え
- 精度: A100/L4 は bf16、T4 は fp16（T4 は bf16 の専用回路がなく、実測 2 TFLOPS と遅い）
- 検証: train 分子の5%を分子単位で取り分ける
- 1エポックごとに `last.pt` を保存し、切断されても続きから再開できる

## 5. この先の実験計画
1. 事前学習あり（`init='pretrained'`）で学習し、1エポックの時間を実測して予算を見積もり直す
2. 比較用に、事前学習なし（`init='scratch'`）を短く回し、転移学習の効果を数字で確かめる
3. 補助損失（`contrib_w`）、エポック数、学習率などを調整
4. うまくいかなければ2位方式に切り替える（前処理と評価のコードは共通）
